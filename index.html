Description

Overview

The exchange quirks ontology (xqo) provides vocabulary to classify and relate certain operational contract variants of exchange-listed derivatives, to capture the instantiation templates of exchange-listed derivatives, as well as their instantiations.

Why?

FIBO's official ontology (much like FIX) stop at exchange-specific implementations, and instead refer to the possibility of extending the standard unofficially as needed. And while FIX covers pre-trade, FIBO is generally post-trade, and neither cover analytical workflows like universe selection, exchange selection, order type selection, trading parameters nor important dates associated with the exposure.

How?

A class, xqo:ExecutionModality is introduced, and the most prominent modalities are identified and introduced as classes in their own right. Moreover, a class xqo:OperationalVariant is introduced, itself a subclass of gufo:Role to capture the operational contract (or chain, or synthesis) as a variant of the outright contract (or chain, or synthesis). Then for each of the modalities a variant is introduced, itself a subclass of xqo:OperationalVariant which is inferred if a resource states

R xqo:executedVia xqo:<Modality> .

=>

R a xqo:<Modality>Variant .

and, conversely:

R a xqo:<Modality>Variant .

=>

R xqo:executedVia [
        a xqo:<Modality> 
] .

Where?

The official github repository contains the published ontology.

The project's canonical home is http://schema.ga-group.nl/xqo/.

TAM c

IRI http://schema.ga-group.nl/xqo/TAM
Description

Modality in which a futures trade is priced at a session marker.
Scope Note

It is either unambigious which marker is referenced, for example if the trading venue only publishes a single session marker, or TAM markers are indistinguishable, and the combination of base contract plus marker type is not unique.

If one needs to uphold the uniqueness of base contract and marker type, or distinguish several TAM markers specifically they should be introduced as subclasses of xqo:TAM.

Datatype Properties

ordinal dp

IRI http://schema.ga-group.nl/xqo/ordinal
Description

Relates a futures contract to its ordinal value, implying an ordering and adjacency.
Scope Note

Note that this value is supposed to be an ordinal, i.e. non-repetitive, and easily sortable by using ORDER BY in SPARQL queries. That means exchange provided discriminators à la H6, M4, or Z7 don't fit the brief because H7 < Z4, and the Z4 of the noughties (2004-12) equals the Z4 of the twenties (2024-12). Use "2006-03"^^xsd:gYearMonth, "2014-06"^^xsd:gYearMonth, or "2027-12"^^xsd:gYearMonth instead. Some contracts don't have an xsd datatype or an ISO 8601 notation, use raw strings in those cases (e.g. "2006-Winter", "2010-Season-2", etc.)

The exchange discriminator can be captured by xqo:discriminator.
Range Literal
